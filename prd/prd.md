## 1. 产品目标与范围

Unsent 为暂时没有准备发送的话提供表达和保留空间。当前版本围绕「信箱、说说、小灯」验证三个问题：用户能否理解入口分工、完成表达与保留流程、正确理解主动记录及数据边界。

目标用户与场景延续 Brief，仍属于待验证假设。当前没有用户研究、留存或情绪改善数据，不以功能可运行代替产品价值验证。

### 1.1 当前范围

- 信箱：新建、编辑、草稿保存、信件保存、状态筛选。
- 说说：三种示例陪伴方式、发送文字、新对话、用户文字转存。
- 小灯：按日期手动记录冲动次数，按分档显示亮度。
- 基础：移动端界面、页面导航、浏览器本地保存与必要提示。

### 1.2 不包含

真实 AI、账号与后端、云同步、实际向他人发送消息、真实联系行为监测、长期对话记忆、提醒奖励、诊断治疗。信件删除、日历更正删除和数据导出恢复也未提供，后续另行评估。

### 1.3 优先级

- P0：核心表达、保存、记录和避免误导所需的行为。
- P1：体验完整性、可访问性与异常处理完善。
- P2：后续探索，需明确需求后再排期。

优先级表示本次文档建议的重要程度，不表示已确定发布日期。

## 2. 信息架构与用户流程

| 页面 | 主要内容 | 主要操作 |
| --- | --- | --- |
| 信箱 | 信件总数、状态筛选、列表、空状态 | 写信、编辑、保存 |
| 说说 | 陪伴方式、消息区、输入框、示例说明 | 发送、转存、新对话 |
| 小灯 | 月份导航、日历、图例、选中日期详情 | 选择日期、加一次、首次确认零次 |

### 2.1 表达后保留

进入说说 → 选择陪伴方式 → 输入并发送 → 查看示例回应 → 点击收进信箱 → 在信件窗口检查或编辑自己的文字 → 保存 → 从信箱再次查看。

转存不会自动清空聊天，也不会直接发送给任何人。

### 2.2 写信与继续编辑

进入信箱 → 新建 → 输入标题或正文 → 关闭窗口形成草稿 → 重新打开 → 补充正文 → 保存为未寄出的信。

### 2.3 主动记录

进入小灯 → 选择今天或过去日期 → 记录一次冲动，或首次确认零次 → 查看次数与亮度 → 在同一浏览器和站点下刷新后回看。

## 4. 信箱需求

### MAIL-01 新建与输入

- 优先级：P0；状态：已有实现。
- 点击「写一封新信」打开空白编辑窗口。
- 标题手动输入上限为 80，正文为 20000，沿用当前浏览器输入框长度限制；技术计数细节在 spec 中说明。
- 保存时去除标题和正文首尾空白；标题留空时使用「给此刻的自己」。
- 正文为空或仅空白时，主动保存应被阻止，并提示先写下一点内容。
- 验收：空正文不能保存为未寄出；有正文、无标题可以保存并获得默认标题。

### MAIL-02 草稿保存

- 优先级：P0；状态：已有实现，失败处理见 ISSUE-01。
- 对新信件或原有草稿，点击关闭按钮或触发编辑窗口取消事件时，只要标题或正文非空，便保存为草稿。
- 标题和正文均为空的新信件关闭后不创建记录。
- 只有标题也可以形成草稿，但不能在正文为空时主动保存为未寄出。
- 此处为关闭窗口时保存，不是逐字自动保存；直接刷新或关闭浏览器前未关闭编辑窗口的改动不保证保留。
- 验收：关闭有内容的新信件后，草稿列表可见；本地保存成功时刷新后能恢复。

### MAIL-03 保存与再次编辑

- 优先级：P0；状态：已有实现，边界问题见 ISSUE-01、ISSUE-03。
- 点击「收进信箱」将有正文的信件保存为「未寄出」。
- 编辑已有信件应更新原记录，不额外生成一封。
- 已保存信件再次编辑后关闭，仍保持「未寄出」状态，不降为草稿。
- 成功写入浏览器后显示成功提示。
- 验收：草稿可转为未寄出；编辑后记录总数不增加，内容更新。

### MAIL-04 列表、筛选与空状态

- 优先级：P1；状态：已有实现。
- 提供全部、未寄出、草稿三种筛选，按最近更新时间倒序排列。
- 列表项显示日期、状态、标题与正文预览，点击可编辑。
- 顶部数量为全部信件数，包括草稿，不随筛选改变。
- 无匹配记录时显示空状态；草稿筛选使用草稿提示。
- 验收：两种状态分别筛选正确；编辑后的信件按更新时间重新排序。

### 信件状态说明

| 操作 | 原状态 | 结果 |
| --- | --- | --- |
| 有内容时关闭 | 新信件 / 草稿 | 草稿 |
| 正文非空时主动保存 | 新信件 / 草稿 | 未寄出 |
| 编辑后保存或有内容时关闭 | 未寄出 | 未寄出 |
| 空白新信件关闭 | 无 | 不创建 |
| 将已有内容全部清空后关闭 | 已有记录 | 当前保留旧记录，见 ISSUE-03 |

## 5. 说说需求

### TALK-01 陪伴方式

- 优先级：P0；状态：已有实现。
- 默认「听我说说」，另有「安慰一下」「一起想清楚」，同时仅选中一种。
- 切换后下一次发送使用所选方式对应的预设回复；切换本身不生成消息，也不改写历史回复。
- 当前每种方式有两条预设文本，按本次会话发送轮次交替选取，不根据语义生成。
- 验收：三种方式均可选中；下一条回复属于当前方式；历史消息保留。

### TALK-02 输入与回应

- 优先级：P0；状态：已有实现。
- 单次手动输入上限为 8000，沿用浏览器输入框限制。
- 空内容或仅空白不生成消息；有效发送后展示用户文字和一条示例回复，并清空输入框。
- 消息按发送顺序显示；用户输入以文本展示。
- 页面显著标注「当前为示例回应，尚未接入 AI」。
- 验收：有效提交仅新增一条用户消息和一条示例回复；空白提交不新增。

### TALK-03 收进信箱

- 优先级：P0；状态：已有实现，长度问题见 ISSUE-04。
- 没有已发送用户消息时提示先表达，不打开空信件。
- 有消息时打开新信件窗口，标题预填「那些还没发出去的话」。
- 正文仅包含本次会话中已发送的用户文字，按顺序以空行连接；不包含示例回复和输入框中未发送内容。
- 打开窗口不等于已经保存；用户可编辑、主动保存或关闭形成草稿。
- 转存不清空原聊天；再次转存会打开另一封新信件，当前无自动去重。
- 验收：转存内容与用户发送内容对应，保存后可在信箱回看。

### TALK-04 新对话与刷新

- 优先级：P0；状态：已有实现。
- 存在已发送内容时，第一次点击新对话提示先保留文字；4 秒内再次点击执行重置，超时后需重新确认。
- 无已发送内容时可直接重置。
- 重置清空已发送会话并显示初始引导，不删除已存信件，当前保持所选陪伴方式。
- 整页刷新不保留会话；需要保留的用户文字应先存入信箱。
- 当前重置不清空输入框中未发送的文字，这项行为需结合体验反馈评估。
- 验收：第一次点击不丢失会话，确认后清空；已存信件不受影响。

## 6. 小灯需求

### LIGHT-01 月份与日期

- 优先级：P0；状态：已有实现。
- 初始显示当前月份并选中今天；按用户设备本地日期判断今天。
- 日历以周一为每周首列，可以查看历史月份；在当前月份禁用进入下个月。
- 当前月的未来日期不可选择和记录。
- 切到历史月份默认选中该月第一天，返回当前月份默认选中今天。
- 验收：月份天数和星期位置正确，未来日期禁用，详情对应选中日期。

### LIGHT-02 记录一次冲动

- 优先级：P0；状态：已有实现。
- 未记录日期首次点击 +1 后为 1；已有记录每次加 1；零次记录可继续增加。
- 更新选中日期的次数、亮度和保存反馈。
- 记录来自用户主动填写，不根据聊天条数或真实联系行为自动生成。
- 验收：连续操作产生正确次数，其他日期不变，本地保存成功后刷新保持。

### LIGHT-03 首次确认零次

- 优先级：P0；状态：已有实现。
- 仅在日期未记录时允许确认零次；已记录后禁用该按钮。
- 今天显示「今天 0 次」，历史日期显示「这天 0 次」。
- 未记录不自动当作零次；零次按钮不能用于清除已有次数。
- 验收：首次确认后显示 0 次，按钮禁用；再点击 +1 变为 1 次。

### LIGHT-04 亮度与解释

- 优先级：P0；状态：已有实现。

| 次数 | 状态 |
| --- | --- |
| 未记录 | 虚线轮廓 |
| 0 | 最亮 |
| 1–2 | 中亮 |
| 3–5 | 微亮 |
| 6 及以上 | 熄灯 |

图例和详情须能帮助用户理解次数分档。亮度不作为个人评价、心理状态诊断或产品效果指标。验收覆盖未记录、0、1、2、3、5、6 这几个边界值。

## 7. 数据与异常要求

| 编号 | 优先级 / 状态 | 需求与现状 |
| --- | --- | --- |
| DATA-01 | P0 / 已有实现 | 信件、草稿和小灯记录在当前浏览器同一站点来源下保存；不声称跨设备同步或永久备份。 |
| DATA-02 | P0 / 待改进 | 写入失败时提示未保存，不能仅凭页面显示更新就声称持久保存成功；信箱关闭窗口的处理需改进，见 ISSUE-01。 |
| DATA-03 | P1 / 部分实现 | 数据读取异常应提示问题，避免伪装成正常空数据；当前小灯有异常提示，信件部分数据格式异常提示不足，见 ISSUE-02。 |
| DATA-04 | P0 / 已有说明，待体验验证 | 清除网站数据会丢失本地记录；改变站点来源不会迁移数据；本地保存不代表加密。检查用户是否能够理解这些限制。 |

本版本没有主动上传上述记录的业务逻辑。未来新增 AI、统计或后端前，需要重新明确数据用途和产品说明。

## 8. 界面与可访问性要求

- UX-01（P1，待验收）：移动端主要操作可见且可触达；检查 320、375、430 像素宽度及桌面展示，避免横向溢出、底部导航遮挡和键盘弹出后无法操作。
- UX-02（P1，部分实现、待验收）：按钮、输入框、导航有可理解名称；选中状态不只靠颜色；可使用键盘完成主要流程，检查焦点可见与弹窗关闭后的焦点返回。
- UX-03（P1，待验收）：长标题、长正文、多条聊天和跨月日历仍可阅读与操作，不以一屏布局为由裁掉必要内容。
- UX-04（P0，已有说明、待体验验证）：陪伴文案不宣称具备未实现能力；小灯含义清楚，不将低冲动次数描述为人格或治疗成效。

以上是待执行的检查要求，不代表已完成兼容性或可访问性认证。

## 9. 已发现差距与待决事项

以下来自静态代码核对，本次只记录，不修改产品代码。

| 编号 | 建议优先级 | 现状与影响 | 建议验收目标 |
| --- | --- | --- | --- |
| ISSUE-01 | P0 | 信件写入失败虽提示错误，但窗口仍关闭，列表内存状态已更新；用户可能误以为保存完成。 | 保存失败时保留可恢复的编辑内容与明确失败状态，提供可理解的重试路径。 |
| ISSUE-02 | P1 | 信件数据读取失败有提示，但可解析的非数组数据或部分无效项可能被静默忽略。 | 明确异常数据提示和恢复策略，避免直接把异常当作首次使用。 |
| ISSUE-03 | P1 | 已有信件被清空后关闭，旧内容保留；已保存信件有标题但正文清空时关闭，则可能保存空正文，与主动保存规则不同。 | 明确清空、关闭和保存之间的统一规则；在确认方案前保留为待决事项。 |
| ISSUE-04 | P1 | 多轮聊天拼接可能超过正文输入框的 20000 长度，程序预填与手动输入限制不一致。 | 明确超长内容如何提示、完整保存或拆分，不静默截断；方案待评估。 |
| ISSUE-05 | P1 | 编辑窗口通用提示称关闭保留草稿，但已保存信件关闭仍为未寄出。 | 按编辑状态调整提示，使文字与实际状态一致。 |

日历记录更正删除、信件删除、数据导出恢复、真实 AI 等属于待评估扩展，不因出现在本表附近而自动加入本轮开发。
