## 1. 架构与运行

项目为纯静态前端，无框架、构建流程、后端、账号和 AI 接口。用户操作由浏览器事件处理，持久数据写入 localStorage，聊天会话保留在当前页面内存和 DOM 中。

在项目根目录运行：

```sh
python -m http.server 8001 --bind 127.0.0.1
```

访问 http://127.0.0.1:8001/ 或 http://127.0.0.1:8001/chat.html。使用静态服务器而非直接打开 file:// 文件，以保持可预测的站点来源和浏览器 API 行为。该命令用于本地体验，不代表生产服务方案。

代码依赖原生 dialog、localStorage、crypto.randomUUID、Object.hasOwn、replaceAll 等浏览器能力，未提供兼容性降级。crypto.randomUUID 依赖安全上下文；本地 loopback 预览和实际 HTTPS 部署仍应分别验证。当前未定义经过实测的最低浏览器版本。

## 2. 文件职责与加载顺序

| 文件 | 职责 | 依赖 |
| --- | --- | --- |
| index.html | 默认首页，包含三个页面、底部导航、信件弹窗与提示容器 | mobile.css、lights.js、mobile.js |
| chat.html | 与首页相同的完整入口，支持已有直达路径 | 同上 |
| mobile.css | 页面布局、颜色、信封与灯泡造型、信箱、聊天、日历、弹窗和响应式样式 | HTML 与脚本生成的类名 |
| lights.js | 初始化日历 DOM、日期选择、次数计算、存储与渲染 | 浏览器日期和存储 API |
| mobile.js | 挂载日历、页面路由、信件编辑与筛选、示例聊天及转存 | 入口 DOM、lights.js 先完成初始化 |
| lights.css | 早期独立日历样式，两个当前入口均未引用 | 当前页面运行不依赖该文件 |

### 2.1 初始化顺序

1. 浏览器解析 HTML 和 mobile.css。
2. 页面底部的 lights.js 同步执行，在自执行函数内读取日历数据，创建 .lights-panel 并追加到 body，绑定事件并首次渲染。
3. mobile.js 同步执行，将 .lights-panel 移入 #calendar-mount，读取信件数据并绑定交互。
4. 调用 route()，根据 URL hash 决定可见页面。

两个脚本通过 DOM 存在性耦合，没有导出的模块接口。不可直接颠倒顺序或添加会导致乱序的 async；若重构为模块，需要建立明确初始化调用，并验证缺少日历节点时不会导致整页逻辑失败。

### 2.2 双入口与遗留文件的处理约定

本次核对 index.html 与 chat.html 的 SHA256 相同，内容一致。当前保留两个入口，以兼容已有地址；不在文档整理中改成重定向或删除入口。

后续修改公共 HTML 时应同步两个入口并检查一致性。若将来合并，需要验证旧地址及其 hash 导航仍可访问，另行记录变更。

lights.css 暂时保留。后续清理时先检查整个项目的引用和历史用途，再在单独提交中删除；本次未删除文件，也不将其重新加入样式加载。

## 4. 数据模型与存储

### 4.1 信件

存储键：unsent.letters.v1。值为 JSON 数组，以下仅为格式示例，不是真实用户数据：

```json
[
  {
    "id": "example-letter-id",
    "title": "给此刻的自己",
    "body": "示例文字",
    "status": "draft",
    "updated": 0
  }
]
```

| 字段 | 新记录的类型与来源 | 用途 |
| --- | --- | --- |
| id | string；crypto.randomUUID() | 标识信件，编辑时复用 |
| title | string；输入 trim 后取值，空则使用默认标题 | 列表与编辑标题 |
| body | string；输入 trim 后取值 | 信件正文 |
| status | draft 或 saved | 筛选及状态展示 |
| updated | number；Date.now() 毫秒时间戳 | 最近更新排序和日期展示 |

当前读取只检查数组以及记录中 id、title、body 的字符串类型；未完整校验 status、updated、重复 id。顶层非数组静默回到空列表，部分无效记录被过滤。未知状态可能在全部列表显示为未寄出，却无法进入 saved 筛选；无效时间戳影响日期与排序。以上是校验缺口，不是推荐的数据契约。

### 4.2 小灯

存储键：unsent.impulses.v1。值为日期到非负安全整数的 JSON 对象：

```json
{
  "2026-09-19": 0,
  "2026-09-20": 3
}
```

- 键为设备本地日期 YYYY-MM-DD，不使用 UTC 日期截取。
- 缺少键表示未记录；值 0 表示用户明确记录零次；不把 null 写成未记录状态。
- 内存 records 使用无原型对象；countFor() 通过 Object.hasOwn 判断键是否存在，缺少键时返回 null。
- 读取时要求顶层为非数组对象，日期键符合格式、值为非负安全整数；不合法项被忽略。
- 日期只检查格式，未验证日期真实存在或是否为未来日期；如 2026-02-31 仍可能被读入但不会成为正常日历日期。

### 4.3 保存边界

| 内容 | 保存位置 | 整页刷新后 |
| --- | --- | --- |
| 信件与已关闭保存的草稿 | localStorage | 写入成功则恢复 |
| 小灯次数 | localStorage | 写入成功则恢复 |
| 已发送用户文字 turns | mobile.js 内存 | 清空 |
| 对话展示与示例回复 | DOM | 重建初始界面 |
| 当前模式、筛选、编辑状态 | 内存 / DOM | 恢复默认状态 |
| 编辑框中尚未触发保存的改动 | DOM | 不保证保留 |
| 页面选择 | URL hash | 有效 hash 对应页面继续显示 |

localStorage 按协议、主机、端口组成的来源隔离。两个入口同源，因此共享持久数据；重新加载入口仍会重置会话。当前每次写入整个数组或对象，没有跨标签页 storage 事件同步或冲突合并，多标签页同时修改可能互相覆盖。

### 4.4 数据兼容约定

当前没有迁移、导出、恢复、加密或备份流程。后续改变键名或字段时，应先定义旧版读取及迁移策略，验证成功前保留原数据；不可用清空 localStorage 作为常规升级方案。迁移与异常测试使用独立浏览器环境和虚构数据，不覆盖用户真实内容。

## 5. 页面路由与展示

route() 从 location.hash 去掉首个 # 后取值，仅接受 mail、talk、calendar，其余回退为 talk，但不主动改写无效 hash。

路由依次设置各 .page 的 hidden、导航 active 类和 aria-current，滚动到顶部；进入 mail 时调用 renderLetters()。切换页面不销毁 DOM，不重置 turns 或信件编辑相关内存。

页面容器最大宽度为 440px，底部导航固定定位，样式使用动态视口高度与安全区处理。具体移动键盘、长文本和日历高度效果仍须实测，不以存在 CSS 规则作为通过依据。

## 6. 信箱实现

### 6.1 内存状态

- letters：已读取或当前操作后的信件数组。
- filter：all / saved / draft，默认 all。
- editing：当前编辑的信件 id；新建与聊天转存时为 null。
- toastTimer：提示隐藏定时器；notify() 更新文本并重设约 3.2 秒隐藏时间。

### 6.2 打开与提交

openLetter(letter) 设置 editing、预填输入并调用 showModal()。新建为空白，聊天转存传入没有 id 的标题和正文，因此按新信件处理。

storeLetter(status) 当前执行顺序：

1. trim 标题与正文；两者都为空则返回 false。
2. 根据 editing 查找旧记录，生成或复用 id。
3. 若旧记录为 saved，则继续为 saved；否则使用传入状态。
4. 更新 updated，替换旧记录或添加新记录到内存 letters。
5. persist() 将整个数组写入浏览器。
6. 无论写入成功与否都刷新列表，再返回保存结果。

表单提交额外检查正文非空；成功才显示保存成功提示，但调用方无论写入是否成功都会关闭窗口。关闭按钮以 draft 调用保存后关闭；cancel 事件也调用 draft 保存，未阻止原生取消行为。

### 6.3 状态与边界

| 起点 / 操作 | 当前结果 |
| --- | --- |
| 新建或草稿，有内容关闭 | draft |
| 新建或草稿，正文非空主动保存 | saved |
| 已保存信件，有内容关闭或提交 | 保持 saved |
| 新建，标题与正文均空时关闭 | 不创建 |
| 已有信件，内容全部清空后关闭 | storeLetter 返回 false，旧记录仍在 |
| 已保存信件，仅保留标题后关闭 | 可保存空正文，状态仍为 saved |
| 保存失败 | 内存已改变、列表已刷新、窗口关闭；持久数据可能仍是旧值 |

最后三项是 PRD 已记录的差距，不能在实现文档中暗示已经修复。

### 6.4 列表

renderLetters() 先清空列表；总数取 letters.length；根据 filter 筛选并按 updated 降序。标题、正文、日期使用 textContent 写入，正文预览通过 CSS 单行截断。空列表根据筛选类型显示提示。点击卡片打开原信件。

## 7. 示例聊天实现

mode 默认 listen，对应 comfort、clarify 两个其他值。模式切换只更新选中状态，不清空会话。

chat-form 提交时 trim 输入；空白返回；有效文本加入 turns，通过 message() 写入 DOM，然后从当前模式的两条预设回复中按 (turns.length - 1) % 2 选择一条。轮次属于整个会话，不为每种模式分别计数。回复是同步本地文本，没有网络请求、模型推理、流式返回和上下文理解。

message() 通过 textContent 显示文本，配合 pre-wrap 保留换行。信件正文和用户消息不作为 HTML 执行。

### 7.1 转存

save-chat 将 turns.join('\n\n') 作为新信件正文；不包含示例回复与未发送输入。只有打开弹窗，后续由信箱保存流程写入。再次转存没有去重或关联更新。

### 7.2 新对话

存在 turns 时首次点击设置按钮 dataset.ready，并安排 4 秒后删除；期间再次点击执行重置。重置清空 turns 和消息 DOM，显示引导语并移除 ready。当前不重置 mode，也不清空未发送输入。

当前确认定时器未保存为独立可取消句柄。快速连续开启多轮确认时，旧定时器可能清除新一轮 ready，缩短确认窗口；这是静态核对发现的补充风险，待复现并回填 PRD。

### 7.3 输入长度

HTML maxlength 分别为标题 80、正文 20000、聊天 8000，按 UTF-16 代码单元计数，不等于所有可见字符数量。当前 JS 没有统一长度校验；程序赋值的聊天转存不能依赖 maxlength 自动截断或阻止。超长转存行为需要明确产品规则并实测，不静默丢弃文字。

## 8. 小灯实现

### 8.1 日期与内存

selected 初始为 localDay()，month 为当前月第一天，storageIssue 保存读写异常提示。localDay() 使用本地年、月、日并补零。

render() 每次重新读取今天，用 (month.getDay() + 6) % 7 计算周一首列偏移，通过下个月第零天计算当月天数。每个日期按钮带 aria-label、aria-pressed，今天带 aria-current=date；未来日期禁用。

moveMonth(delta) 切换月份并默认选中月初；目标为当前月时选中今天。禁用当前月的下一月按钮是 UI 限制，moveMonth 本身没有独立的未来月份校验。

### 8.2 计数与状态

| countFor 返回值 | level 返回值 | 展示 |
| --- | --- | --- |
| null | empty | 未记录 |
| 0 | bright | 最亮 |
| 1、2 | medium | 中亮 |
| 3～5 | dim | 微亮 |
| ≥6 | off | 熄灯 |

+1 使用 (countFor(selected) ?? 0) + 1，新增结果须为安全整数；超出安全整数范围时当前不保存，也无专门提示。零次按钮在已有记录时禁用，处理函数直接调用 save(0)，规则主要由 UI 禁用保证。

### 8.3 保存与渲染

save(value) 首先阻止未来日期写入，随后更新内存记录、尝试持久化、重绘日历并显示成功或失败提示。写入失败不回滚内存，因此可在当前页面看到未持久化的记录。

save(null) 内部包含删除分支，但界面没有调用它的入口，不能据此宣称支持用户删除记录。

页面重新可见时触发 render()，更新今天及禁用状态，但不自动更换 selected 或 month，也不重新读取其他标签页写入的数据。跨午夜、跨月和系统时钟变化须实测。

## 9. 异常差距与修复方向

本节为未实现建议，不是本次交付的代码改动。

| 关联问题 | 技术原因 | 后续方向 |
| --- | --- | --- |
| PRD ISSUE-01 | 先改内存再写存储；失败后调用方仍关闭弹窗 | 明确保存结果类型，保留编辑内容并允许重试；新建重试复用稳定 id，避免重复记录 |
| PRD ISSUE-02 | 信件读取只校验部分字段，异常项被忽略 | 定义完整 schema 校验、异常提示和恢复策略；验证 status、updated 与重复 id |
| PRD ISSUE-03 | 主动保存和关闭采用不同正文校验 | 产品确定清空语义后统一校验与状态转换，不擅自把清空等同删除 |
| PRD ISSUE-04 | 转存程序赋值与输入框长度约束分离 | 明确长内容保存或拆分规则，再在统一入口校验 |
| PRD ISSUE-05 | 固定弹窗文案未区分已有 saved 信件 | 根据编辑状态显示对应提示，关闭按钮可访问名称也同步 |
| 补充：多标签页覆盖 | 启动时读取一次，每次全量写回 | 如纳入范围，定义 storage 同步、冲突检测及用户提示策略 |
| 补充：确认定时器竞争 | 新对话旧定时器未清除 | 保存并取消旧句柄，核对快速连续操作；先复现再修复 |

补充风险尚未执行复现，也未更新上游需求编号。待确认后同步 PRD，避免技术建议自行变成已批准需求。

## 10. 检查与验收方法

### 10.1 静态检查

- 核对两入口引用与脚本顺序，比较文件内容或哈希。
- 核对 DOM id、数据属性和监听器对应，避免修改 HTML 后脚本找不到元素。
- 如本机已有 Node.js，可运行以下语法检查；它们不执行浏览器行为：

```sh
node --check mobile.js
node --check lights.js
```

### 10.2 浏览器检查

沿用 PRD 的 AC-01～AC-14，不复制一套不同的产品验收标准：

| 范围 | 重点技术证据 |
| --- | --- |
| 导航与双入口 | 每个入口的 hash、可见页面、导航状态和控制台错误 |
| 信箱 | 草稿与 saved 转换、原 id 是否复用、刷新后存储一致性 |
| 聊天 | 模式选择、文本安全展示、转存排除回复、新对话确认窗口 |
